# Укрепление

Bastion сам выставляет заголовки безопасности (строгая Content Security Policy без inline-скриптов и стилей, HSTS, frame-ancestors none) и не заводит сессий на публичных страницах. Проверки ниже касаются сервера вокруг него.

## Список проверок

- Корень веб-сервера — только каталог public; var, src, vendor и build недоступны.
- Код принадлежит root и только читается пользователем PHP-FPM; писать этот пользователь может лишь в var и extensions.
- PHP-FPM работает в отдельном пуле, open_basedir ограничен каталогом сайта.
- Второй фактор для администраторов и редакторов остаётся обязательным.
- Почта настроена — сброс пароля работает без доступа к shell.
- Медиа хранятся в S3-совместимом хранилище, а не рядом с кодом.

## За CDN

За CDN соединение приходит от CDN, а не от посетителя. Доверяйте заголовку с адресом клиента только от диапазонов вашего CDN, на уровне веб-сервера. Иначе AppSensor, который блокирует адреса нарушителей, заблокирует узлы CDN целиком.

Публичные страницы не ставят cookie и кэшируются на пять минут; /admin и /install не кэшируются никогда.

## Наблюдение

Панель администратора перечисляет слабые места конфигурации (Degraded Mode). Журнал аудита только дополняется и сцеплен HMAC; запускайте bin/bastion audit:verify ежедневно и поднимайте тревогу при ошибке.
