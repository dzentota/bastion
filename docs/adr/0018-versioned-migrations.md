# ADR-0018: Версионированные миграции, применяемые админом

- Статус: принято
- Дата: 2026-10-31

## Контекст

`Schema::ensureCurrent()` на каждом запросе выполняет идемпотентные `CREATE TABLE IF NOT EXISTS`. Изменять существующие колонки так нельзя, а i18n, ревизии и иерархия страниц (docs/roadmap.md) требуют именно этого. Кроме того, схему сейчас может изменить любой анонимный запрос. Платформа — shared-хостинг без shell (ADR-0002), поэтому только CLI не подходит.

## Решение

- Миграции — классы `Migration` с нумерованным id и DDL для SQLite и MySQL, перечисленные явным списком в `Migrations\Catalog` (каталог не сканируется: подброшенный файл не становится миграцией). Применённые записываются в `?_schema_migrations` (id, SHA-256 DDL, время, кто применил). Расхождение суммы или запись, неизвестная коду, блокирует обновление.
- Текущий `Schema::statements()` заморожен как миграция `0001_baseline`. Её DDL идемпотентен, поэтому существующие установки применяют её поверх своих таблиц через тот же экран обновления.
- Обычные запросы схему не меняют. При неприменённых миграциях публичный сайт работает в режиме обслуживания, а админка показывает экран «Обновить базу».
- Применение из админки (`/admin/database`): только Admin (`settings.manage`), свежий TOTP-код с защитой от повтора, CSRF. Перед первой ожидающей миграцией — резервная копия в `var/backups` (SQLite — `VACUUM INTO`, MySQL — JSON-дамп таблиц `bst_*`); сбой копии прерывает обновление. Каждая миграция — запись `schema_migrated` в журнале аудита. Под файловой блокировкой, состояние перечитывается под ней, каждая миграция в транзакции (в SQLite DDL откатывается, в MySQL — только запись учёта).
- `bin/bastion migrate` остаётся альтернативой для тех, у кого есть shell.

## Последствия

- Веб-процесс по-прежнему имеет DDL-права (иначе shared-хостинг не работает), но использовать их можно только через аутентифицированный шаг с подтверждением.
- Abuser Stories в `threat-model/schema-migrations.php`: unauthorized-migration, tamper-applied-migration, plant-migration, migration-race, migration-data-loss, half-migrated-site. Attack Tests — `tests/Attack/Database`, `tests/Attack/Http/DatabaseUpdateHttpTest.php`.
- SQLite-соединение получило busy_timeout и повтор переключения в WAL: тест гонки показал, что одновременное открытие новой базы падало с «database is locked».
- Откат — восстановление из бэкапа; down-миграции не поддерживаются.
